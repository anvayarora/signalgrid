# Snowflake cost attribution

The supplied CSV contains report-level observation fields, not a native `SNOWFLAKE.ACCOUNT_USAGE.QUERY_HISTORY` extract. SignalGrid therefore keeps two clearly separated calculation paths:

1. `SIGNALGRID_OBSERVATION_COSTS` and `SIGNALGRID_REPORT_COST_SUMMARY` calculate only what the supplied rows support. Negative credits are invalid and excluded. A zero-view row has a `NULL` cost per view. Report-level numeric values use medians because the same report appears 20 times without timestamps. No row is called “latest,” and rows are not summed into a monthly company total.
2. `SIGNALGRID_SIMULATED_ACCOUNT_USAGE_ATTRIBUTION` demonstrates a Snowflake-compatible query-log path only when each query has an explicit `REPORT_ID` label. It is intentionally backed by a table named `SIGNALGRID_SIMULATED_QUERY_HISTORY`; it must not be presented as observed production evidence.

Run `01_schema.sql`, upload and stage the file using the executable `COPY INTO` flow in `02_stage_and_quality.sql`, then run `03_attribution.sql` and `04_validation.sql`. Staging keeps Snowflake's `SOURCE_FILE_CONTENT_KEY` and source row number; that content key is not a SHA-256 digest. The Node importer records the exact source-file SHA-256, while `SOURCE_FILE_SHA256` remains null in Snowflake unless a separately reviewed manifest supplies it. `05_account_usage_reference.sql` is the production-shaped path using `SNOWFLAKE.ACCOUNT_USAGE.QUERY_ATTRIBUTION_HISTORY` plus `WAREHOUSE_METERING_HISTORY`; it uses Snowflake's actual query-attributed compute when available and keeps tagged, untagged, idle/unattributed, and cloud-service amounts separate. Hour-crossing queries are allocated by overlap duration only for hourly reconciliation, preventing double-counting. The optional `SIGNALGRID_CREDIT_RATE` table holds a reviewable USD-per-credit assumption; no currency rate is asserted by the case-study data.
